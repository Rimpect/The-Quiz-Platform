# Quiz Platform — Frontend

Фронтенд-часть платформы для проведения квизов. Разработана в рамках дипломной работы КГУ.

Одностраничное приложение (SPA) на React + Vite: создание и прохождение квизов,
командные игры в реальном времени (через WebSocket), личный кабинет, лидерборды,
достижения и админ-панель.

**Статус разработки:** 🚧 В активной разработке  
**Статус билда:** 📦 Pre-MVP  
**Покрытие тестами:** ❌ 0%

## Архитектура

Проект построен по методологии **Feature-Sliced Design (FSD)** — код разделён на слои
по уровню ответственности. Зависимости направлены строго сверху вниз: слой может
импортировать только то, что лежит ниже него.

| Слой         | Назначение                                                            |
| ------------ | --------------------------------------------------------------------- |
| `app`        | Инициализация приложения: роутинг, провайдеры, error boundary         |
| `pages`      | Страницы — собираются из виджетов и фич                               |
| `widgets`    | Самостоятельные блоки интерфейса (Header, Quiz, FinishQuiz, лобби)    |
| `features`   | Пользовательские сценарии (авторизация, редактор квиза, таймер, игра) |
| `entities`   | Бизнес-сущности и работа с их данными (user, quiz, leaderboard …)     |
| `shared`     | Переиспользуемый код: API-клиент, конфиг, UI-кит, утилиты             |

Для импортов между слоями настроены алиасы (см. [vite.config.js](vite.config.js)):
`@app`, `@pages`, `@widgets`, `@features`, `@entities`, `@shared`, `@MockData`.

```js
import { Header } from '@widgets/Header'
import { API_URL } from '@shared/config/env'
```

## Структура проекта

```
client/
├── public/            # Статика (звуки таймера, иконки и т.п.)

│   ├── pages/         # Страницы приложения

│   ├── features/      # Сценарии (auth, quiz-editor, game-lobby …)

├── Dockerfile         # Multi-stage сборка → раздача через nginx
├── nginx.conf         # Конфиг nginx (раздача SPA + прокси /api)
└── vite.config.js     # Конфиг сборки, алиасы, dev-прокси
```

## Начало работы

```bash
# Клонировать репозиторий
git clone https://github.com/Rimpect/The-Quiz-Platform.git

# Перейти в папку фронтенда
cd The-Quiz-Platform/client

# Установить зависимости
npm install

# Запуск development-сервера (http://localhost:5173)
npm run dev
```

> Для полноценной работы нужен запущенный бэкенд на `http://localhost:8000`
> (см. [../server/README.md](../server/README.md)). Dev-сервер сам проксирует
> запросы `/api` на бэкенд — настраивать CORS не требуется.

## Переменные окружения

Конфигурация задаётся через файл `.env` в папке `client/` (доступна в коде через
`import.meta.env`):

| Переменная     | Назначение                          | Значение по умолчанию |
| -------------- | ----------------------------------- | --------------------- |
| `VITE_API_URL` | Базовый путь к API                  | `/api`                |
| `VITE_BASE`    | Базовый путь сборки (`base` в Vite) | `/`                   |

`VITE_API_URL=/api` означает, что фронт обращается к API относительным путём — и в
dev (через прокси Vite), и в проде (через nginx) всё идёт с одного origin.

## Связь с бэкендом

- **REST API** — все запросы идут на `${VITE_API_URL}` (по умолчанию `/api`).
  Клиент с авто-обновлением токена: [src/shared/api/client.js](src/shared/api/client.js).
- **WebSocket** — командные игры в реальном времени подключаются к
  `/api/game/ws/<sessionId>` на том же хосте (см.
  [src/features/game-lobby/model/useGameSocket.js](src/features/game-lobby/model/useGameSocket.js)).

В режиме разработки оба канала проксируются на `http://localhost:8000`
(настройка `server.proxy` в [vite.config.js](vite.config.js)).

## Линтинг и форматирование

В проекте настроены три инструмента для поддержания качества кода:

| Инструмент    | Назначение                     | Конфиг            |
| ------------- | ------------------------------ | ----------------- |
| **ESLint**    | Проверка JavaScript/React кода | `.eslintrc.js`    |
| **Stylelint** | Проверка CSS/SCSS кода         | `.stylelintrc.js` |
| **Prettier**  | Форматирование кода            | `.prettierrc`     |

### Что проверяется?

#### ESLint

- Синтаксические ошибки
- Порядок импортов (import/order)
- Неиспользуемые переменные
- Правила React (хуки, ключи в списках)
- Отсутствие `console.log` в production

#### Stylelint

- Порядок CSS свойств
- Дублирование селекторов
- Несуществующие классы
- Единообразие написания цветов (HEX/rgba)

#### Prettier

- Отступы (2 пробела)
- Одинарные кавычки
- Точки с запятой в конце
- Максимальная длина строки (100 символов)

### Как пользоваться?

```bash
# Запустить все проверки (без автоисправления)
npm run lint

# Автоматически исправить все ошибки
npm run lint:fix

# Только JS проверка
npm run lint:js          # проверить
npm run lint:js:fix      # проверить и исправить

# Только CSS проверка
npm run lint:css         # проверить
npm run lint:css:fix     # проверить и исправить

# Только форматирование
npm run format
```

## Сборка и деплой

Production-сборка кладётся в папку `dist/`:

```bash
npm run build
```

В проде фронт собирается и раздаётся через **nginx** внутри Docker-контейнера
(multi-stage [Dockerfile](Dockerfile)): nginx отдаёт статику SPA и проксирует
запросы `/api` на бэкенд. Вся платформа (фронт + бэкенд + PostgreSQL + Redis)
поднимается одной командой из корня репозитория:

```bash
docker compose up -d --build
```
